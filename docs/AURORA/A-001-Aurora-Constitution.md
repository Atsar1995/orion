# 3. Core Principles

Aurora is governed by eight constitutional principles. Every engineering mission, product decision, and agent behaviour must comply.

## 3.1 Principle I — AI First

**Marketing intelligence is embedded from inception — not bolted on after launch.**

| Rule | Requirement |
|------|-------------|
| **Default intelligence** | Every module exposes AI-assisted workflows as the primary path |
| **Agent availability** | Relevant specialized agents are available in every module context |
| **Proactive recommendations** | Aurora surfaces optimization opportunities without user prompt |
| **Learning loop** | Campaign outcomes feed agent context for future recommendations |
| **No dumb forms** | Data entry interfaces prefer conversational and intelligent input |

### AI First Boundaries

AI First does **not** mean AI Only. Aurora agents accelerate human marketers — they do not replace strategic judgement, brand stewardship, or executive accountability.

## 3.2 Principle II — Human Oversight

**Humans retain authority over every consequential marketing action.**

| Action Class | Default Governance |
|--------------|-------------------|
| **Content draft generation** | Auto-approved for internal review · publish requires approval |
| **Creative asset generation** | Review required before external use |
| **Ad campaign launch** | Approval required · budget threshold configurable |
| **Social media publish** | Approval required · emergency override with audit |
| **Email send (>100 recipients)** | Approval required |
| **WhatsApp broadcast** | Approval required · compliance check mandatory |
| **Budget increase >10%** | Executive approval required |
| **Brand voice change** | Brand manager approval required |

### Oversight Hierarchy

```
Executive / Founder
        ↓
Brand Manager / CMO
        ↓
Marketing Director
        ↓
Channel Manager / Specialist
        ↓
AI Agents (propose only)
```

No agent may bypass the configured approval hierarchy.

## 3.3 Principle III — Automation

**Repeated marketing tasks are candidates for intelligent automation.**

| Automation Tier | Description | Examples |
|-----------------|-------------|----------|
| **Tier 1 — Assist** | AI suggests · human executes | Copy suggestions · headline variants |
| **Tier 2 — Semi-auto** | AI executes · human approves | Scheduled posts · email drafts · ad variants |
| **Tier 3 — Conditional auto** | AI executes within guardrails | A/B test rotation · bid adjustments within budget cap |
| **Tier 4 — Full auto** | AI executes · human monitors | Reporting · analytics alerts · SEO monitoring |

Tier 4 never applies to external publish actions without explicit tenant configuration and audit logging.

### Automation Safeguards

- Every automated action produces an audit log entry
- Automation rules are version-controlled and reviewable
- Emergency pause ("kill switch") halts all automation tenant-wide within 60 seconds
- Automation boundaries are configurable per brand · per channel · per role

## 3.4 Principle IV — Multi-Business

**Aurora natively supports operators managing multiple businesses from one account.**

| Capability | Requirement |
|------------|-------------|
| **Business entity** | Top-level organizational unit with isolated data boundary |
| **Business switching** | Seamless context switch without re-authentication |
| **Cross-business reporting** | Aggregated analytics for holding companies and agencies |
| **Business-level billing** | Separate subscription and usage metering per business |
| **Business-level integrations** | Channel connections scoped to business entity |

### Multi-Business Use Cases

| Operator | Configuration |
|----------|---------------|
| **Founder with 3 companies** | 3 business entities · shared login · separate brands |
| **Holding company** | Parent business · subsidiary businesses · consolidated reporting |
| **Agency** | Agency business · client businesses as sub-entities |

## 3.5 Principle V — Multi-Brand

**Brand identity is a first-class entity — not a tag or folder.**

| Brand Attribute | Governed Element |
|-----------------|------------------|
| **Voice & tone** | Agent prompt context · content review rules |
| **Visual identity** | Colour palette · typography · logo usage rules |
| **Messaging pillars** | Core themes · prohibited topics · required disclaimers |
| **Channel presence** | Per-brand social accounts · ad accounts · email domains |
| **Approval policy** | Per-brand workflow configuration |
| **Knowledge base** | Brand-specific product · audience · competitor context |

### Brand Isolation Rules

1. No agent may cross-reference Brand A context when operating on Brand B
2. Creative assets are brand-scoped in storage with enforced namespace isolation
3. Analytics attribution is brand-specific with optional rollup
4. Brand deletion requires executive confirmation and 30-day archive retention

## 3.6 Principle VI — Enterprise Security

**Security is constitutional — not a feature checklist.**

Aurora inherits ORION enterprise security foundations and extends them with marketing-specific controls.

| Security Domain | Requirement |
|-----------------|-------------|
| **Authentication** | ORION Identity · SSO · MFA · session management |
| **Authorization** | RBAC · brand-scoped permissions · least privilege |
| **Data encryption** | At rest · in transit · field-level for PII |
| **Audit logging** | Immutable · tamper-evident · 7-year retention (enterprise) |
| **Secrets management** | Platform secrets vault · no credentials in agent context |
| **API security** | OAuth 2.0 · scoped tokens · rate limiting |
| **Compliance** | GDPR · CCPA-ready · marketing consent tracking |
| **Penetration testing** | Annual third-party assessment (enterprise tier) |

### Marketing-Specific Security

| Risk | Control |
|------|---------|
| **Unauthorized publish** | Approval gates · role verification · channel token scoping |
| **Brand impersonation** | Brand-scoped credentials · connection verification |
| **Prompt injection** | Agent sandboxing · input sanitization · output filtering |
| **Data leakage across tenants** | Strict tenant isolation · query scoping · integration token isolation |
| **AI-generated misinformation** | Fact-checking hooks · source attribution · human review for regulated industries |

## 3.7 Principle VII — Scalability

**Aurora must scale from one brand to ten thousand without architectural redesign.**

| Scale Dimension | Target |
|-----------------|--------|
| **Tenants** | 100,000+ |
| **Brands per tenant** | 500+ |
| **Concurrent campaigns** | 10,000+ per tenant |
| **Content assets** | 10M+ per tenant |
| **Daily publish actions** | 1M+ platform-wide |
| **Agent invocations** | 10M+ daily platform-wide |
| **Analytics events** | 100M+ daily ingestion |

### Scalability Principles

1. Stateless application tier — horizontal scaling
2. Event-driven architecture for publish · analytics · agent orchestration
3. Content delivery via CDN — origin storage separated
4. Database partitioning by tenant_id
5. Agent workloads queued and rate-limited per tenant tier
6. Integration API calls respect provider rate limits with intelligent backoff

## 3.8 Principle VIII — Transparency

**Every AI recommendation, automated action, and performance metric must be explainable.**

| Transparency Requirement | Implementation |
|--------------------------|----------------|
| **Agent rationale** | Every agent output includes "Why I recommend this" |
| **Confidence level** | High · Medium · Low on all AI recommendations |
| **Data sources** | Attribution of metrics to source integration |
| **Algorithm disclosure** | Optimization logic documented for enterprise customers |
| **Audit trail** | Who · what · when · why for every consequential action |
| **Version history** | Content · creative · campaign configuration versioning |

### Transparency Commitments

- Aurora never presents AI-generated content as human-created without disclosure configuration
- Performance metrics display data freshness timestamp and source
- Budget optimization decisions include before/after projection
- Failed agent actions surface error context to authorized users — not generic failure messages
