# 3. Implementation Strategy

## 3.1 Implementation Principles

Derived from IMP-1 through IMP-10 and ES specification binding principles (100 total across modules). Key enforcement:

- Every PR references work package ID and spec section
- No merge without tests · review · coverage check
- No new patterns without ADR
- Stubs must match spec stub contracts exactly

## 3.2 Incremental Delivery

```
Foundation → Identity → Intelligence Core → Domain Modules → Integration Layer → Release Gate
     ↓            ↓              ↓                  ↓                  ↓              ↓
  WP-A001     WP-A002      WP-A003/A004      WP-A005–A007      WP-A008–A010    v0.1.0-dp
```

Each increment produces a deployable, testable, health-checked module.

## 3.3 Vertical Slice Approach

Each work package delivers a **complete vertical slice**:

| Layer | Deliverable |
|-------|-------------|
| Domain | Services · entities · business rules |
| Persistence | Repository · migration · RLS |
| Integration | Events · facade · module wiring |
| Quality | Unit · integration · security tests |
| Operations | Health check · metrics · jobs |

No horizontal "all repositories first" layering.

## 3.4 Module Sequencing

| Order | WP | Mission | Rationale |
|:-----:|-----|---------|-----------|
| 1 | WP-A001 | A-007 | Platform · boot · wiring — all modules depend |
| 2 | WP-A002 | A-008 | Identity · RBAC · RLS — all modules depend |
| 3 | WP-A003 | A-009 | Knowledge — workforce · content depend |
| 4 | WP-A004 | A-010 | Workforce — content · campaign · SEO AI depend |
| 5 | WP-A005 | A-011 | Content — publish · campaign depend |
| 6 | WP-A006 | A-012 | SEO — parallel with A-005 after A-004 |
| 7 | WP-A007 | A-013 | Campaign — depends content · workforce |
| 8 | WP-A008 | A-014 | Analytics — depends campaign · content · SEO |
| 9 | WP-A009 | A-015 | Publishing — depends content · campaign |
| 10 | WP-A010 | A-016 | Integrations — enables live connectors |

## 3.5 Dependency Management

| Mechanism | Purpose |
|-----------|---------|
| WP dependency graph | Appendix A · no WP starts until deps met |
| Contract tests | Cross-module interface validation |
| Facade stubs | Upstream modules expose typed stubs until live |
| Integration sprint | Dedicated cross-module validation per release gate |
| Daily standup blockers | Dependency issues escalated L1→L2 within 24h |

## 3.6 Quality-First Philosophy

| Gate | Threshold | Enforced At |
|------|-----------|-------------|
| Unit test coverage | ≥ 85% | PR merge |
| Integration tests | Per spec minimum count | WP completion |
| Security isolation tests | 100% pass | WP completion |
| Linter | Zero errors | PR merge |
| Architecture compliance | Checklist pass | Sprint review |

## 3.7 Evidence-Driven Completion

A work package is **complete** only when:

1. All acceptance criteria met (§4)
2. Evidence bundle submitted (§7)
3. Mission Lead sign-off
4. QA Lead sign-off
5. Security Lead sign-off (where applicable)
6. ARB compliance confirmation
