# P-012.6 Roster Guide

**Mission:** P-012.6 – Attendance, Leave & Rostering  
**Module:** HCM Rostering

## Overview

Roster planning assigns employees to work shifts over a defined period with overlap validation and publication workflow.

## Roster Lifecycle

```
draft → published → archived
```

## Shift Assignment

Each assignment links an employee, shift, and calendar date:

```typescript
rosterService.create({
  departmentId: "dept-operations",
  periodStart: "2026-08-01",
  periodEnd: "2026-08-07",
  assignments: [
    { employeeId: "emp-hcm-001", shiftId: "shift-day", rosterDate: "2026-08-01" },
  ],
}, context);

rosterService.publish(rosterId, context);
```

## Overlap Validation

The rules engine rejects:

- Duplicate shift assignments on the same day
- Overlapping shift time windows on the same day

## Shift Changes

`changeAssignment` publishes `ShiftChanged` with workflow template `hcm.shift.change`.

## REST API

- `GET /api/hcm/roster` — list rosters
- `POST /api/hcm/roster` — create roster
- `POST /api/hcm/roster/publish` — publish roster

## Events

- `ShiftAssigned` (on publish)
- `ShiftChanged` (on assignment change)
