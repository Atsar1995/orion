# P-012.6 Policy Configuration Guide

**Mission:** P-012.6 – Attendance, Leave & Rostering

## Organization Policies

All time policies are scoped by `organizationId`. Seed data for `org-orania` includes default policies and calendars.

## Leave Policies

| Field | Purpose |
|-------|---------|
| `accrualRatePerMonth` | Days/hours accrued per month |
| `maxCarryForward` | Maximum balance carried to next period |
| `requiresApproval` | Whether requests need manager approval |
| `allowPartialDay` | Half-day and partial-day leave support |

### Default Policies (org-orania)

| Leave Type | Accrual/Month | Carry Forward | Approval |
|------------|---------------|---------------|----------|
| annual | 1.75 | 10 | Required |
| sick | 0.75 | 0 | Auto-approved |
| compensatory | 0 | 5 | Required |

## Work Calendars

Configure working hours per weekday:

```typescript
calendarService.saveWorkCalendar({
  code: "STD-5D",
  name: "Standard 5-Day Week",
  workingHours: { monday: 8, tuesday: 8, wednesday: 8, thursday: 8, friday: 8 },
  weekStartsOn: "monday",
  active: true,
}, context);
```

## Holiday Calendars

Multiple holiday calendars per organization are supported. Assign by code or query all active calendars.

## Workflow Templates

| Template Key | Use Case |
|--------------|----------|
| `hcm.leave.approval` | Leave request approval |
| `hcm.attendance.correction` | Attendance correction |
| `hcm.overtime.approval` | Overtime approval |
| `hcm.shift.change` | Shift change approval |

Events include `workflowTemplateKey` and `workflowInstanceId` in the IIL payload for Workflow Platform consumption.

## Attendance Policies

- Organization-specific attendance is enforced via employee active status
- Remote and half-day statuses are first-class attendance values
- Biometric and mobile sources are recorded via `source` field
