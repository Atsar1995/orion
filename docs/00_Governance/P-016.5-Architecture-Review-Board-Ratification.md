## 2. ADR Review Decisions

### 2.1 ADR-013 — Durable Intelligent Integration Layer

| Field | Assessment |
|-------|------------|
| **Architecture Assessment** | Resolves TD-PLATFORM-003 and AG-002 at architecture level. Durable transport abstraction, standardized envelope, idempotency, dead-letter, replay, and vendor-neutral adapter pattern align with P-016.2 O2 (durable cross-domain integration) and Commitment A3 (Finance hub via IIL). Complements ADR-007 persistence without duplicating store governance. |
| **Risks** | Transport adapter selection deferred — implementation teams must not pre-select broker before Gate 4 ES. Dual-run migration from in-process IIL requires careful certification. Partition ordering complexity at scale. |
| **Dependencies** | ADR-007 · ADR-011 · ADR-012 · P-006 · ES-097. Enables ADR-014 · ADR-016 · Finance Gate 5. |
| **Conditions of Acceptance** | Gate 4 platform ES for durable IIL before Gate 5 transport code. TECHNICAL_DEBT.md update on implementation mission. Security Architect envelope classification rules enforced at ingress. |
| **Decision** | **Accepted** |

---

### 2.2 ADR-014 — Cross-Domain Event Contracts

| Field | Assessment |
|-------|------------|
| **Architecture Assessment** | Establishes constitutional event contract law — canonical `eventType` naming, schema registry, ownership matrix, validation rules, and contract lifecycle. Closes Finance inbound catalogue gap (ES-FIN-002 §4). HCM `CustomEvent` migration path via compatibility shim is adequate. Finance hub inbound/outbound priority chains are explicitly catalogued. |
| **Risks** | HCM catalogue v2 migration effort. Schema registry maintenance overhead. Over-registration of domain-only events. Producer/consumer dual-version coordination during deprecation windows. |
| **Dependencies** | ADR-013 (transport). Enables ES-FIN-002 · P-009 Gate 5 · ADR-016 · ADR-017. Complemented by ADR-020 (facade/API versioning). |
| **Conditions of Acceptance** | Priority schemas **Registered** before Finance Gate 5 production inbound processing. Registry path `docs/11_Governance/EventContracts/` populated in implementation mission — not required for acceptance. HCM and Finance Domain Leads acknowledge priority contract list (§4.2). |
| **Decision** | **Accepted** |

---

### 2.3 ADR-015 — Domain Service Boundaries

| Field | Assessment |
|-------|------------|
| **Architecture Assessment** | Constitutional bounded-context law — HCM reference replication, IIL-only cross-domain authoritative integration, forbidden repository imports, public facade single-entry, Finance ACL at inbound boundary, and domain boundary matrix. Resolves TD-DOMAIN-PERSIST-001 architectural layer and CRM facade convergence mandate. |
| **Risks** | CRM pre-handbook facade convergence effort before Gate 5. Developers bypassing facade via dynamic imports — mitigated by architecture tests at Gate 5. Intelligence must not source authoritative Brief signals from facade reads alone (BM-006). |
| **Dependencies** | ADR-013 · ADR-014. Enables ES-FIN-002 EC-001/EC-008 · CRM Gate 5 · Hospitality Gate 5. Related ADR-020 for facade breaking changes. |
| **Conditions of Acceptance** | CRM Gate 4 facade audit scheduled before CRM Gate 5. Replication checklist (§7.4) mandatory for all authoritative domains at Gate 5 certification. |
| **Decision** | **Accepted** |

---

### 2.4 ADR-020 — Versioning & Domain Compatibility

| Field | Assessment |
|-------|------------|
| **Architecture Assessment** | Enterprise semver and compatibility model spanning platform releases, domain facades, event contracts (aligned with ADR-014 §6), REST API majors, repository migrations, and configuration. Dual-version windows (max 2 majors · 180 days) and deprecation law (90 days minimum) are certifiable. Scope boundary with ADR-014 is explicit — no governance conflict. |
| **Risks** | Dual-version operational complexity. MAJOR change ARB latency. Store migration rollback discipline. HCM legacy event version semantics during replay. |
| **Dependencies** | ADR-013 · ADR-014 · ADR-015 · ADR-012 · ES-097 §7. Enables ES-FIN-002 §4.4 · multi-domain evolution. |
| **Conditions of Acceptance** | Compatibility CI deferred to Gate 5 implementation mission. Finance catalogue remains at `eventVersion: 1` until schema registration mission. |
| **Decision** | **Accepted** |
