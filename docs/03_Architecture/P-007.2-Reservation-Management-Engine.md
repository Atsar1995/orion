# P-007.2 — Reservation Management Engine Architecture

**Mission:** P-007.2 — Reservation Management Engine  
**Epic:** P-007 Hospitality Workspace v1.0  
**Status:** Production-ready (in-memory persistence)  

---

## Purpose

The Reservation Management Engine is ORION's canonical booking platform. All future modules (Revenue Management, CRM, Billing, Channel Management, Guest Experience) must consume this engine — not implement independent booking logic.

---

## Architecture

```
lib/hospitality/reservations/
├── index.ts                    # HospitalityReservationFacade
├── reservation-mapper.ts       # Legacy ↔ ReservationRecord
├── reservation-events.ts       # IIL event publisher
types/hospitality-reservation.ts # Canonical domain types
```

### Services

| Service | Responsibility |
|---------|----------------|
| `ReservationService` | Full lifecycle CRUD, modify, actions |
| `AvailabilityService` | Date-range availability against inventory |
| `AllocationEngine` | Auto-assign and manual inventory allocation |
| `ConflictDetectionEngine` | Blocking conflicts and overbooking detection |
| `ReservationRulesEngine` | Validation and transition rules |
| `CalendarService` | Daily/weekly/monthly/timeline views |
| `ReservationSearchService` | Multi-criteria search |
| `RateLookupService` | Rate plan reference from accommodation types |

Public facade: `hospitalityReservationService`

---

## Reservation Lifecycle

```
inquiry → quote → provisional → confirmed → modified
  → checked_in → checked_out → archived
  ↳ cancelled / no_show
```

---

## Integration with Inventory Model (P-007.1)

- Reservations reference `accommodationTypeId` and optional `inventoryItemId`
- `Allocation` records track room assignment per stay segment
- Availability queries use `InventoryItem` from inventory repository
- Conflict detection prevents double-allocation of inventory units

---

## Platform Integration

| Platform | Integration |
|----------|-------------|
| Executive Brief | Arrivals, departures, booking pace, VIP arrivals, overbookings |

## Reference Implementation Rule

Billing, front office, and channel modules must call `hospitalityReservationService` — not maintain parallel reservation state.
