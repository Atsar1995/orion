# P-008.3 — Proposal, Contract & Commercial Agreements Platform Architecture

**Mission:** P-008.3 — Proposal, Contract & Commercial Agreements Platform  
**Epic:** P-008 Customer Relationship & Revenue Platform  
**Domain:** D-003 Commercial Agreements  
**Status:** Production-ready (in-memory persistence)  

---

## Purpose

The Commercial Agreements Platform manages the complete lifecycle of commercial offers, negotiated terms, contractual commitments, renewals, and pricing agreements. All entities reference Universal Party (`partyId`) and Opportunity where applicable — they do not own customer identity.

**CTO rule:** Executed agreements are immutable business records. Subsequent changes create new versions while preserving complete negotiation and approval history.

### Services

| Service | Responsibility |
|---------|----------------|
| `ProposalService` | Proposal CRUD, version control, lifecycle transitions |
| `QuotationService` | Quotation CRUD, issue workflow |
| `ContractService` | Contract CRUD, signing, amendments, expiry |
| `RateAgreementService` | Corporate, seasonal, promotional, negotiated rates |
| `ApprovalWorkflowService` | Request and decide approvals |
| `RenewalService` | Renewal processing and dashboard |
| `AgreementAnalyticsService` | Registry view and Executive Brief signals |

Public facade: `crmAgreementsService`

---

## Lifecycle Model

```
Draft → Review → Approved → Issued → Accepted | Rejected
  → Signed → Active → Expired | Renewed → Archived
```

Version history is stored in `AgreementVersion[]` on proposals and contracts.
