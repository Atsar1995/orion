# P-007.4 — Front Office Operations Platform Architecture

**Mission:** P-007.4 — Front Office Operations Platform  
**Epic:** P-007 Hospitality Workspace v1.0  
**Status:** Production-ready (in-memory persistence)  

---

## Purpose

The Front Office Operations Platform is the operational control center for guest arrivals, in-house management, departures, and accommodation movements. **Stay** is the primary operational entity — reservations create stays; front office manages stays.

---

## Architecture

```
lib/hospitality/front-office/
├── index.ts                    # HospitalityFrontOfficeFacade
├── front-office-events.ts      # IIL event publisher
types/hospitality-front-office.ts
lib/hospitality/data/seed-front-office.ts
```

### Services

| Service | Responsibility |
|---------|----------------|
| `OperationalDashboardService` | Queues, KPIs, occupancy summary |
| `CheckInService` | Identity, registration, room assignment, inventory occupied |
| `CheckOutService` | Folio balance, inventory dirty, guest timeline |
| `AccommodationAssignmentService` | Room assignment with readiness checks |
| `OccupancyService` | Vacant clean/dirty, occupied, OOO board |
| `StayService` | Extensions, room moves, upgrades/downgrades |
| `FrontOfficeRulesEngine` | Stay status validation |

Public facade: `hospitalityFrontOfficeService`

---

## Operational Workflow

```
Reservation (P-007.2) → Stay (expected)
  → Room Assignment → Check-in (checked_in) → In-house Management
  → Check-out (checked_out) → Housekeeping (dirty room)
```

---

## Platform Integration

| Platform | Integration |
|----------|-------------|
| Reservations (P-007.2) | Lifecycle actions, room modify |
| Guests (P-007.3) | Timeline entries, VIP context |
| Inventory (P-007.1) | Room status sync on check-in/out |
| Executive Brief | Occupancy, VIP in-house, operational delays |
| IIL | `StayCheckedIn`, `StayCheckedOut`, `RoomAssigned`, `GuestMoved` |

---

## CTO Recommendation

Stay is the canonical operational entity. Housekeeping, billing, and analytics shall consume Stay — not duplicate reservation state.
